# MeeTap Highlight Track 设计（纪要要点高亮）

> 状态：已确认，待实现
> 日期：2026-08-11
> 所属：CLI v1.5 线新轨道（轨道7）
> 分支：`feature/track7-highlight`

## 背景与目标

MeeTap 生成的会议纪要（`meeting-notes.md`）信息密度高，通读一遍仍需时间。本轨道新增一个**独立后处理命令** `meetap highlight`，用 LLM 给已生成的纪要补一层 `<mark>` 要点高亮，让读者一眼抓住关键数字、核心判断和案例结果。

`<mark>` 是标准 HTML 标签，在 VS Code / Typora / GitHub / 浏览器等主流 Markdown 渲染器中显示为黄色底色，无需额外依赖。

## 范围与边界

**做：**
- 新增 `meetap highlight [dir]` 命令，对已有 `meeting-notes.md` 原地补高亮。

**不做（YAGNI）：**
- 不在录制/生成流程后自动触发（纯手动）。
- 不改邮件 HTML 与 PDF 渲染链路（高亮**仅落在 markdown 源文件**）。
- 不做高亮密度可调参数（`light/normal/heavy`）。
- 不做用户可覆盖的高亮模板三级查找。

这些都留待有明确需求时再加。

## 命令与行为

```
meetap highlight [dir]
```

- `dir` 默认解析为最新会话目录，解析规则与 `meetap again` 一致（复用现有目录解析逻辑）。
- 读取 `<dir>/meeting-notes.md`，调 LLM 只做高亮标注，**原地写回同一文件**。
- **幂等**：对已高亮过的文件再次运行，先剥掉旧 `<mark>`/`</mark>` 再重新标注，不产生嵌套标签。
- 手动触发，默认不介入录制后的自动流程。

## 架构：复用现有 LLM 调用链

不新写 LLM 调用代码，复用现有的模型分派逻辑（`summarize_via_bedrock` / `summarize_via_claude_code`，见 `src/meetap:793` 一带的分派），仅替换 prompt 内容与读写的文件。

好处：超时、重试、异常分类、模型选择等成熟逻辑（v1.5.2 引入）全部继承，无需重复实现与维护。

实现时若现有分派与「生成纪要」耦合过紧，允许做**最小限度的抽取**：把「给定 prompt 文件 + 输出文件，跑 LLM」这段抽成一个可复用的内部函数，供 `summarize` 与 `highlight` 共用。不做超出此目的的重构。

## 「只加 mark 不改字」的保证（关键约束）

LLM 存在顺手改写正文的风险。本设计用两道防线杜绝纪要被破坏：

1. **Prompt 层**：严令逐字保留原文，只允许在原文中插入 `<mark>` 与 `</mark>` 标签，不得增、删、改任何其他字符（含标点、空格、换行）。

2. **校验闸门（写回前）**：
   - 取 LLM 输出，剥掉所有 `<mark>`/`</mark>` 标签，得到 `stripped_output`。
   - 取原始 `meeting-notes.md`，同样剥掉所有已有 `<mark>`/`</mark>` 标签（应对重标场景），得到 `stripped_original`。
   - 两者**逐字节比对**：
     - **一致** → 写回 `meeting-notes.md`。
     - **不一致** → 拒绝写入，保留原文件不动，打印本地化告警（提示模型改动了正文，未写入）。

即使模型不老实，也绝不会破坏用户的纪要。

## 高亮策略（固定，写进独立 prompt 模板）

策略固化进新模板 `share/meetap/prompts/highlight.md`：

- **只标三类内容**：
  1. 关键数字 / 指标（增长倍数、百分比、金额、日期、deadline 等）。
  2. 核心判断与结论（会议的关键定性、决策、观点）。
  3. 案例结果（标杆客户、迁移成果、客户评价等的**结论性表述**）。
- **密度控制**：每段最多 1-2 处；`## 关键结论` 区每条列表项 1-2 处。
- **不标**：
  - `行动计划 & 待定事项` 表格（本身已是结构化要点，再标反而干扰）。
  - 末尾 Meetap 签名页脚。
  - 顶部 blockquote 元信息区（会议时间/性质/关键词/与会人员）。
- 目标：突出重点而非满页泛黄。

## 测试要点

- 幂等性：对同一文件连续运行两次，结果一致，无嵌套 `<mark>`。
- 校验闸门：构造「模型改了字」的场景（可用 mock/替身），确认拒绝写入且原文件不变。
- 目录解析：`highlight` 不带参数时取最新会话，与 `again` 行为一致。
- 模板缺失/损坏：给出明确的本地化错误，不静默失败。
- 空/异常纪要：`meeting-notes.md` 不存在时给出清晰提示。

## 与其他轨道的关系
