# MeeTap Lite —— 轻量客户端（会议自动弹出）

> 本文档用于对齐 `feature/meetap-lite` 分支的目标、边界与开工方式。**这是一份起步说明，不是最终设计**，标注为「待定」的部分欢迎在此分支上讨论、补充或直接修订。

## 一、这个分支要做什么

一个 **macOS 上的轻量客户端**：在后台静默运行，**检测到会议开始时自动弹出**，让用户一键开始录制 —— 把现有 MeeTap 的「先开终端、敲命令」这一步省掉。

核心价值：**降低触发成本**。用户不用记命令、不用手动开录，会议一来客户端自己冒出来，点一下就录。

## 二、定位与边界（重要）

MeeTap 现有演进分两条独立的线，本客户端属于**围绕 CLI 线的轻量前端**，不是第三条线：

- ✅ **做**：会议检测 + 自动弹窗 + 一键触发录制的「轻前端」。
- ✅ **复用**：录制 / 转写 / 摘要能力**全部交给现有 CLI**（`src/meetap`），本客户端只负责「什么时候弹、弹出来长什么样、点了之后调用哪个命令」。
- ❌ **不做**：不重写音频采集、转写、摘要逻辑；不改 CLI 核心行为（如需 CLI 配合，走接口约定，见下）。
- ❌ **不碰**：不引入与 CLI 线冲突的技术栈决策（CLI 线明确保持 Bash + Swift、不上 Rust）。

> 一句话：**Lite = 触发器 + 界面壳，引擎仍是 CLI。**

## 三、职责划分

| 环节 | 归属 | 说明 |
| :-- | :-- | :-- |
| 会议检测 | **Lite** | 判断"会议开始了" |
| 自动弹出提示 | **Lite** | 弹窗/通知，提供"开始录制 / 忽略"操作 |
| 启动录制 | **CLI** | Lite 调用 `meetap start ...` |
| 音频采集 / 转写 / 摘要 / 发送 | **CLI** | 完全复用现有能力，Lite 不参与 |

## 四、待定的关键问题（欢迎在本分支拍板）

这些是形态相关、需要合作者一起定的点，先列出来，避免各写各的：

1. **技术形态**：菜单栏常驻 app？悬浮窗？还是系统通知横幅？（影响后续所有实现）
2. **会议检测方式**（任选或组合）：
   - 检测会议 app 进程（Zoom / Teams / 飞书 / 腾讯会议）是否启动 / 是否在通话；
   - 读取日历（本地 Calendar / Outlook）里的会议时间；
   - 检测音频活动（有系统音频输出 + 麦克风占用）。
3. **与 CLI 的调用约定**：Lite 用什么方式拉起 CLI？直接 `exec meetap start`？还是 CLI 需要新增一个「被前端调用」的子命令 / 参数？（若需 CLI 改动，请在此文档记录需求，再到 CLI 线实现，避免两边耦合失控。）
4. **技术栈**：Lite 用什么写？（Swift + SwiftUI 菜单栏 app 是较自然的选择，但未定；只要不把 CLI 线拖下水即可。）
5. **误触发处理**：检测到会议但用户不想录时的交互（忽略本次 / 忽略此 app / 稍后提醒）。

## 五、开工指引

```bash
# 克隆并切到本分支
git clone https://github.com/henceman777/meetap.git
cd meetap
git checkout feature/meetap-lite
```

协作约定：

- 本分支基于 `main` 创建，所有改动在此分支或从此分支再拉子分支进行。
- 合入 `main` **必须走 Pull Request**，且需 **1 个 approval**（main 已开分支保护，禁止直推）。
- 提交前请先在本文档「四、待定问题」里把相关决策记下来，方便双方对齐。
