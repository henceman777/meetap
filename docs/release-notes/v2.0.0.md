# v2.0.0 — 不用 BlackHole 了：系统自带的录音，加上日历认会、贴标签和断了接着跑

【不再需要 BlackHole】只用 macOS 自带的 Process Tap 录音，不切输出设备、会议 App 不用配；要求 macOS 14.4 以上

## 从 1.x 升级要做什么

```bash
brew upgrade meetap
meetap setup        # 在每个开录的终端 App 里各跑一次
```

- **只支持 macOS 14.4 以上**（Sonoma 14.4、Sequoia、Tahoe）。还在 macOS 13 上请继续用 1.x。Homebrew 只能按大版本限制系统，所以 14.0–14.3 上也装得上，但 `meetap start`、`meetap setup` 会提示版本太低、不开录。
- **不再需要 BlackHole**：可以 `brew uninstall --cask blackhole-2ch`（别的软件还在用就留着）。卸了以后设备列表里可能还挂着 `BlackHole 2ch`，要重启电脑（或 `sudo killall coreaudiod`）才消失，在那之前别把它选成输出设备。配置里的 `audio_capture = blackhole` 可以删掉；`meetap setup-zoom` / `setup-teams` / `setup-wemeet` 不用再跑。
- **要重新跑 `meetap setup`**：它会检查系统录音授权（2 秒实测，静音就引导你把终端 App 加进 系统设置 › 隐私与安全性 › 屏幕与系统录音），请求一次日历授权（可选，拒绝也不影响录音），并检查 1.x 留下的东西：系统输出、Zoom 的扬声器是不是还指着 BlackHole。权限是授给终端 App 的，在几个终端里开录就各跑一次。
- **会话文件夹里的文件挪了位置**：诊断文件和标签挪进隐藏的 `.meetap/`，`log/` 里只留 `transcript.txt` 和 `meetap.log`，用不上的 `transcribe-raw.json` 转录完就删。老会话照样读得到；想整理成新样子，先 `meetap tidy` 看清单（只列，不动文件），确认后 `meetap tidy --yes`。已经没有音频的老会话，`transcribe-raw.json` 是逐词时间唯一的来源，默认不删。

## 只用系统自带的录音（Process Tap）

**场景**：Zoom、Teams、飞书、腾讯会议、Chime，或者网课、视频，任何在 Mac 上放的声音。

- 录的是整台电脑的声音加你的麦克风，不切输出设备，照常从原来的扬声器、耳机听；会议 App 不用做任何设置，也不用以"机器人参会者"的身份进会。
- **静音报警**：有 App 在放声音、录到的却全是零（多半是授权失效），30 秒内弹通知，写明是哪个 App，格式是"显示名（bundle ID）"。有的 App 一直开着输出、其实没出声（比如 Amazon WorkSpaces 客户端），把通知里括号里那一串加进配置 `zero_alert_ignore` 就不再报。
- 整段录音都是静音时不上传转录，音频留在本地，并弹通知。

## 只敲 meetap 就开录

```bash
meetap              # 等同 meetap start，会开完按 Ctrl-C
meetap -m -d 60     # 开录选项直接跟在后面：只录电脑的声音，60 分钟后自动停
```

只认 `-t`、`-d`、`-b`、`-m` 和它们的长写法；`meetap 周会` 这类写法会报"未知命令"、不开录，免得敲错字误开录音（起名照旧写 `meetap start 周会`）。

## 给会贴标签，以后按标签找回来

```bash
meetap -g 周会                        # 贴给正在录的那场；没在录就贴给最新一场
meetap 20261118_1201 --untag 客户A     # 撤掉一个标签
meetap -g                             # 列这场的标签，以及用过的全部标签和场数
meetap 20261118_1201                  # 显示这场会的时间、时长、纪要、标签、日历
```

- 大小写不敏感，新标签和已有标签相近时提示一句。最新一场开始于 12 小时以前、又没写文件夹时，先问一句再贴。
- 统计范围包括按月整理的 `20YY-MM` 文件夹。标签存在会话的 `.meetap/meta.json`。

## 日历帮纪要认人名和议题

**场景**：系统日历里有这场会，想让纪要用上会名、组织者、参会人和议程。

**怎么用**：在 系统设置 › 互联网账户 里加上公司账户并勾选「日历」，在开录的终端里跑 `meetap setup` 授权（要「完全访问」），之后照常录。

- **怎么认**：停止录音时按录音起止时间收下同时段的会（重叠不到 5 分钟的不算，全天、已取消、已拒绝的不算）。转录完、写纪要之前再认，**时间优先**：起止时间最接近的那场交给模型核对。只有一场时先看标题，标题对得上就用它；标题和说明都明显对不上（比如标题是周会、录到的是新闻时评），就不用日历。几场起止时间完全一样时，按内容选。
- **看哪里**：认出来的会写进 `materials/calendar.md`，和别的资料一起交给模型写纪要。怎么认的写在 `log/meetap.log`、`meetap <文件夹>` 的信息页和纪要完成的通知里（"日历：按时间认出 XXX"、"日历：同时段 1 场，内容对不上，没用"），**不写进纪要**：纪要会转给别人，免得把日历里别的会带出去。
- **隐私**：交给模型的是转录稿开头约 4000 字加结尾约 1000 字、候选会的标题、时间、组织者、前 20 位参会人、会议说明的前 500 字，入会链接、会议号、密码、拨入电话都去掉了，发到的是你自己账号里的 Bedrock。不想多这一次调用，配置写 `calendar = off`。
- 只有 `meetap setup` 会请求日历授权，开录、停止都不弹框；查不到就跳过，不影响纪要。`meetap again` 会重新认；你改过的 `calendar.md` 原样留着。

## 凭证过期、断网时接着跑

**场景**：转录、写纪要时 AWS 凭证过期了，或者网断了一下。

- 查凭证、上传、查转录进度、下载结果、认日历、写纪要、发邮件，每一步失败了都会等着重试（间隔从 10 秒起逐次拉长），每一步最多等 15 分钟。刷新凭证、网络恢复以后自己接着跑完，不用 `again`。
- 通知只弹两次：断掉时第一次失败（分得出是凭证问题就直说），以及 15 分钟还不行、放弃时（写明 `meetap again <会话>`）。
- `meetap again` 时，上一次的转录任务如果已经在 AWS 上转完，直接取结果，不重新上传、不重新转录。
- S3 只删这一场自己的文件（以前转完会清空整个共用的桶，把别的会还在用的文件一起删掉）。
- `log/meetap.log` 接着往后写，每次开头一行分隔，`again` 不再冲掉上一次的日志。

## 录音边录边落盘

以前录音整场攒在内存里，录音过程中 `.m4a` 一直是 32 字节，进程被强杀或断电整场都没了。现在每 10 秒切一片、写完就落盘，最多丢最后 10 秒，剩下的照样能 `meetap again` 出纪要。实测：录到 32 秒时强杀，读出 30 秒；正常停止的成品时长和实际差不到 1 秒。

## 会话文件夹更干净

- `log/` 里只留 `transcript.txt` 和 `meetap.log`，诊断文件、标签在隐藏的 `.meetap/` 里（Finder 里按 Cmd+Shift+. 显示）。
- `meetap tidy` 整理老会话：默认只列清单，加 `--yes` 才执行；音频、纪要、`materials/` 一概不动。

## 其他修复

- 录音只有几秒、一个词都没识别出来时，不再报错退出：日志和通知写"录音里没有识别出说话内容"，不生成纪要；`meetap <文件夹>` 的纪要一行写"没有（录音里没有说话内容）"。转录结果里没有说话人标签时，全部算作 spk_0。
- 帮助、通知的文字对上 2.0 的行为：纪要完成的通知写实际文件名；`stop` 的帮助不再写"恢复音频设备"。
- README 按使用场景改写；实现原理、最小 IAM 权限、开发说明挪进 `docs/`。最小 IAM 权限按默认模型 `global.anthropic.claude-sonnet-5` 的 global 跨区域推理改成三段式写法。

## 真机验收

用几场真实录音验收（macOS 26）：同时段有两场会时认出了对的那场；会议时段里录的是别的东西，判为不用日历；没人说话的录音写明没有说话内容；新录一场，从开录、停止到纪要、邮件整条走通。

## 已知问题

- 自己建的、不是会议的日程（比如提醒自己看视频），模型可能判成和录音对不上，这时纪要不用日历信息，纪要本身不受影响。
- 认日历靠模型判断，可能认错。认错时看纪要完成的通知或 `meetap <文件夹>`，改掉或删掉 `materials/calendar.md` 后 `meetap again`。
- **蓝牙麦克风偶发断流**（1.7.2 就有）：AirPods 通话模式下，麦克风有时开麦后不出数据或出一会儿就停，那段时间本人的声音会缺失，日志里有 `MIC_NO_DATA` / `MIC_STALLED`。根因还在跟进。
- 录音中途把 AirPods 放回盒子（设备真正消失）时，系统声音能否继续录到还没验证过。
- 纪要始终是中文；`language = en-US` 只影响终端界面和通知。
